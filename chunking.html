What the reranker is for the fix

A semantic reranker (a cross-encoder that reads the query and each passage together, not as two separate vectors) re-scores the top-N and pushes the chunk that actually answers the question to the top. The clean, cited UNIT SAFETIES · p.98 section — buried at rank 3–4 on raw cosine — is the kind of chunk it is designed to lift to the top.

And this is the whole point of good chunking: the reranker can only promote a chunk that is complete and self-contained. Give it a mid-word fragment or an HTML table and there is nothing clean to promote. Upstream chunk quality is what makes the reranker — and the citation — work.

In production, retrieval combines BM25 keyword search with vector search, and Azure AI Search’s semantic reranker re-scores the top results over these section-aware chunks.

What this actually shows

Every number here comes straight from the run — no illustrative figures. Held fixed: one chiller manual, the text-embedding-3-large model, and the query. Only the chunking changes. Fixed and Text-Split can even land a relevant chunk at rank 1, so “it retrieved something” is not the test — whether the retrieved passage is a complete, citable answer is. Only the section-aware pipeline returns a self-contained safety section carrying its own page number and OEM · model · chiller tags.

Method: one manual → four chunkers (fixed sliding window · Azure AI Search Text-Split · real Azure Document-Intelligence prebuilt-layout · our custom section-aware pipeline). Every chunk embedded with the same model; ranked by cosine to the same query. Production retrieval then adds BM25 + the semantic reranker above, which is designed to favour clean, section-scoped chunks.
